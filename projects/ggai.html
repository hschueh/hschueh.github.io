The idea

Text adventures have always had a tiny vocabulary: go north, take lamp. LLMs remove that limit, but they bring their own problems. They forget what happened, contradict themselves, and let the player talk their way into anything. GGAI is my attempt at an engine where the model handles the storytelling and a set of structured tools, typed decisions and plain files keep track of what's actually true. Both games are played in Traditional Chinese.

The tagline is meant literally. Almost all of the code was written by AI coding agents working from specs, plans and postmortems I wrote, and the repo keeps an AGENTS.md as its main developer guide.

GGAI MUD — the agentic engine

A single-player, turn-based text adventure. You type what you want to do, in free text, from a Discord thread or the web UI. Each turn is a tick, and one AI agent runs the whole tick through tool calls. It reads the world, rolls dice if needed, has a separate narrator model write the prose, and then writes back only the facts that should persist.

player action (Discord / web) → inbox │ ▼ AgenticTick # one agent, tool calls only 0 read readNpc · readLocation · readQuestStatus · readInventory 1 roll rollDice → d20 + bonus vs DC 2 narrate narrateTick(outcome) → narrator model writes the prose 3 persist updateNpcFact · createLocation · movePlayer · updateQuest … 4 finish finalizeTick(directorNotes) # memo to its next-tick self │ ▼ post-engine (deterministic): quests · dungeons · memory compression │ ▼ durable feed (append-only NDJSON) → stream to Discord / web

Memory modelled on how people remember

Every entity (player, NPC or location) is a Markdown file split three ways. The profile holds current state, the journal is the short-term narrative stream, and memory holds long-term facts. When the journal overflows it's compressed into archives, and when memory overflows a consolidator removes duplicates and prunes it. At the end of each tick the agent also writes director notes to its next-tick self: open threads, what an NPC is planning, foreshadowing it has set up.

When the AI gets it wrong: the Historian

If a player notices the story forgot an NPC's name, they type !fix and describe it. That starts a separate Historian agent. It has the same tools as the tick, minus the dice, the narrator and the ability to end a tick, so it can correct the record without moving the story forward. If it can't find evidence for the claim, it answers 無從查證 (“can't verify”) instead of making something up.

Wishes vs. rules

An “anti-godmode” switch decides how far the player gets to write the outcome. In strict mode, “I find a sword” becomes “I search for a sword” and the dice decide. In the default wish mode the game works as co-writing: outcomes the player spells out come true, and the agent keeps the world consistent, sometimes attaching a cost or a hook to a big gain. In both modes, anything that breaks the world's style, such as guns in a wuxia world, is still blocked.

Worlds, dungeons, and dying

Worlds are templates. There are ones for Jin Yong wuxia, cyberpunk Taipei and a Harry Potter–style school of magic, among others. New locations and NPCs are generated as the player reaches them. Dungeons have floors and scenes, and dying in one lets you rewind and try again, carrying a past-life memory (前世記憶) of how it went last time.

Mountain Road Monkey 跑山ㄍ

A 30-day life-sim about being a Taiwanese motorcycle kid, presented as a phone screen in Next.js. Each morning you pick one thing: a shift at the convenience store, a date with your girlfriend, or a run up the mountain road. On the mountain you choose how to ride each corner (all-out, show-off or steady), the LLM narrates it, and it resolves as perfect, wobble, crash or fatal. NPCs message you over a LINE-style chat, your bank app shows the car loan piling up, and the game ends after 30 days, when debt wins, or when you meet a truck.

Tooling

  • World Forge

    Describe a world in one sentence. It generates a reviewable World Bible, then expands that into a full playable template: a style pack plus a seed world.

  • Narrator Optimizer

    An automated loop that tries to improve the narrator prompt. It uses fixed scenarios, deterministic gates, an LLM judge with 8 scoring dimensions, pairwise comparisons, a holdout set and a budget cap.

  • Playground

    A local sandbox for trying image and video generation (MiniMax, fal) and checking character consistency, moderation and cost before anything goes into a game.

  • Ops scripts

    World linting, a memory-compression audit, tick revert, and a story exporter that stitches journals and archives back into one complete story.

Engineering notes

Constraints that keep it small

No database: game state is Markdown and JSON on disk, which I can read, diff and fix by hand. Every LLM output is checked against a Zod schema before the engine trusts it. All models go through OpenRouter, and each game picks its own in config. The Turborepo workspace shares two packages, an AI layer and Axiom structured logging, and each game deploys to the VPS under PM2 without touching the other.

The feed is the source of truth; the stream is best-effort

The first delivery design was an outbox that was deleted once read. That meant only one client could ever consume it, and a Discord 503 lost the narrative for good. Now every event is appended to a durable per-player feed before it's streamed, and each client reads from its own cursor. A client that disconnects mid-tick doesn't need any resume logic.

Typed decisions instead of judgement calls

Questions like “is this the same NPC?” used to be up to the agent. Now some of them go to Jev, a System One model that answers pre-typed questions (choose, score, true or false) with a confidence value, so a fuzzy judgement becomes a number with a threshold. It's wrapped to fail open: if Jev is down, the tick still completes. The first gate in front of the intent parser is now enforced at 0.28.

Honest result

The first real run of the narrator optimizer, using the same model as production, found 0 winners in 3 rounds for $1.98. Rewording the prompt didn't move the weakest dimension past the noise. What the run did show was that half of all first drafts failed the length gate (short turns ran long and big turns ran short), so that's the production fix to make first.

Status

Deployed privately on a VPS, playable over Discord and the web, and under active development. 19 roadmap tracks cover quests, parties, dungeons, semantic memory, foreshadowing, observability and tick fault tolerance. The repo is private for now.
